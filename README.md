# 土量スキャナ

### ▶ 公開URL： https://kyouhei4444.github.io/doryo-scan/

Android の Chrome で上記を開き、メニューの「アプリをインストール」または
「ホーム画面に追加」を選ぶとホーム画面に入ります（項目名は Chrome の版によって異なります）。

---

Android のスマホカメラで、**平らな面に置いてある土砂の山**や**掘削した穴**を点群にして、
**体積（土量）**を求める現場用アプリです。Android アプリストアを使わない **PWA（ブラウザアプリ）** として作ってあります。

`_apps/sokuryo-nav`（測量座標ナビ）と同じ作りで、HTTPS の URL を Chrome で開き
「ホーム画面に追加」すると、通常のアプリと同じアイコンで全画面起動し、オフラインでも動きます。

---

## 1. できること

| 機能 | 内容 |
|------|------|
| 点群スキャン | ARCore の深度センシングを WebXR 経由で呼び出し、カメラが見ている面までの距離を毎秒数万点読み取って世界座標の点群にする |
| 体積計算 | 土木の**点高法（メッシュ法）**で、基準面からの比高 × 格子面積を積み上げる。山（正）も穴（負）も同じ式 |
| 基準面 | 周りの地面から自動で当てはめ（RANSAC）。手で 3 点以上拾って作ることも、結果画面で上下に微調整することもできる |
| 範囲指定 | 自動（つながっている一番大きい塊）／AR 画面でタップして囲む／平面図でタップして囲む |
| 平面図 | 真上から見た比高の色分け図。指で拡大縮小、外周線・スケールバー・凡例つき |
| 断面図 | 平面図に線を引くと、その線に沿った地表と基準面の断面が出る |
| 土量換算 | ほぐし率 L・締固め率 C を入れて **地山／ほぐし／締固め**の 3 通りと**ダンプ台数**を表示 |
| 距離測定 | AR 画面で 2 点タップ。コンベックスの実測と比べて端末の精度を確かめられる |
| 書き出し | 点群 **PLY**（CloudCompare 等で開ける）／点群 CSV／**格子 CSV（点高法の計算表そのもの）**／断面 CSV／結果 **PNG**／計算条件 JSON |
| 保存 | 端末内（IndexedDB）に格子・点群ごと保存。あとから開いて基準面や範囲を引き直して再計算できる |
| オフライン | 外部の地図や API を使っていないので、圏外の現場でもそのまま動く |

## 3. 動く端末

**ARCore に対応し、かつ ARCore の Depth API に対応している Android 端末**が必要です。

- 対応端末は [Google の一覧](https://developers.google.com/ar/devices) で確認できます（Depth API の列を見てください）
- **ToF センサーは無くても動きます。**その場合はカメラを動かした視差から深度を作ります（depth-from-motion）。ただし精度は落ちます
- ToF／LiDAR 相当のセンサーがある機種（Galaxy S20 Ultra、Note10+、Pixel 8 Pro など）では、はっきり精度が上がります
- iPhone は WebXR に対応していないため**使えません**
- 「Google Play開発者サービス（AR）」が入っていないと動きません（Play ストアから入ります）

アプリを開くと「計測」タブの先頭で端末の対応状況を自動判定します。
判定が終わらない端末もあるので、その場合は「開始」を押して実際に試してください。
深度が使えない端末では、開始時にその旨がはっきり表示されます。

## 4. 使い方

### 撮りかた（ここで精度が決まります）

1. **まず地面から。** 土砂の周りの平らな地面を、ぐるっと 1 周ぶん先に映します。**ここが基準面になり、体積を丸ごと左右します。**
2. **次に土砂本体。** 1〜3m 離れて、山の上・中・下を撫でるように**ゆっくり**動かします。速く振ると深度が出ません（画面上部に警告が出ます）。
3. **ぐるりと回る。** 反対側にも回り込みます。裏側が撮れていないと、その分は周りから補間した推定値になり、体積は**少なめ**に出ます。
4. 画面の点の色が **灰色＝地面 / 青〜赤＝高いところ / 紫＝低いところ**。色が付いていない場所が撮り漏れです。
5. 掘削の穴は、**穴のふちの地面**を先に映してから、上から覗き込むように底を映します。

### AR 画面のボタン

| ボタン | 用途 |
|--------|------|
| **スキャン** | ふつうに撮るだけ |
| **地面点** | 中央の丸を平らな地面に合わせてタップ。3 点以上拾うと、それだけで基準面を作れる（地面が狭いときに有効） |
| **距離** | 2 点タップで実距離。**コンベックスの実測と比べて端末の精度を確認できる** |
| **範囲** | 山の法尻をタップで囲むと、その中だけを集計する |

### 結果画面

- **基準面の上下**スライダー：山の天端を地面と誤認したときや、地面が少ししか写っていないときに動かします。右へ動かすと基準面が上がり、体積は減ります
- **対象とみなす比高**：この値より小さい凸凹は地面とみなして無視します。既定 5cm
- **範囲を囲む**：平面図をタップして多角形を作ると、その中だけを集計します（隣の山を除きたいときなど）
- **断面線**：平面図をなぞると断面図が出ます

黄色い**注意書き**が出たら必ず読んでください。撮り漏れ・基準面の傾き・計測のばらつきを検知して出しています。

### 土量換算

「いま測ったのは」で、測ったものが**地山／ほぐし／締固め**のどれかを選ぶと、3 通りに換算します。

- 積んである残土・掘り出した土 → **ほぐし**
- 掘削前の地面・締まった地盤 → **地山**
- 転圧した盛土 → **締固め**

L（ほぐし率）と C（締固め率）は土質で変わります。既定は普通土の L=1.20 / C=0.90 ですが、
**設計値がある工事では必ず設計書の値を入れてください。**

## 5. 精度について（重要）

**このアプリは概算用です。出来形数量や数量変更の根拠にする場合は、必ず監督員と計測方法を協議してください。**

スマホの深度は、ToF センサーの無い機種ではカメラを動かした視差から作っています。
1 点ごとの誤差は距離の数%あり、5m を超えると急に荒くなります。
たくさんの点を平均するので体積の誤差はそれより小さくなりますが、次の 3 つが効いてきます。

| 誤差の原因 | 効き方 | 対策 |
|------------|--------|------|
| **基準面のずれ** | いちばん効く。面積 20m² の山で基準面が 5cm ずれると、それだけで 1m³ 変わる | 地面を広めに先に撮る。結果画面のスライダーで確認する |
| **撮り漏れ** | 撮れていない側は周囲から補間されるので**少なめに出る** | ぐるっと回り込む。「外周の○%が未計測」の警告を見る |
| **深度のばらつき** | 平滑化と補正で吸収するが、荒れると効いてくる | 明るい場所でゆっくり。1〜3m の距離で撮る |

目安：

- **1 周歩いて撮った小〜中規模の山（〜30m³）**：おおむね **数%〜10数%**
- **裏側が撮れていない・遠くから撮った**：もっと外れます
- **10m を超える大きな山（100m³ 超）**：歩く距離が長くなるほど端末の位置ずれ（ドリフト）が効きます。
  この規模は**ドローン写真測量や TS・GNSS での検測**の領域です。このアプリは目安として使ってください

### 苦手な条件

のっぺりした面（真っ黒な土、水たまり、逆光）／雨天・濃霧／強い直射日光の照り返し／30cm 未満の近距離。

### まずやってほしいこと

「設定」タブの**検証**で、寸法の分かっているもの（コンテナ・箱・一斗缶など）を平らな床に置いて測り、
本当の体積と比べてください。ここで出た誤差が、**その端末での実力**です。
測るたびに記録が残り、平均誤差が出ます。

- **裏側の撮り漏れが「離れた塊が244か所」という的外れな警告になっていた。**

## 7. 計算の中身

### 体積の求めかた（点高法／メッシュ法）

1. 深度画像の各画素を、視点座標を経て世界座標に逆投影して**点群**にする
2. 世界の水平面（XZ）を正方形の**格子**に切り、格子ごとに高さ Y の平均・回数・最小・最大を持つ
3. 土砂の周りの地面から**基準面** `y = a·x + b·z + c` を当てはめる
4. 格子ごとの**比高** `h = 高さ − 基準面` を出す
5. **体積 = Σ（h × 格子面積）**

比高が正なら土量（山）、負なら掘削量（穴）です。
基準面が傾いていても、比高を「水平投影面あたりの高さの差」として足しているので体積は正しく出ます
（2 つの高さ関数の間の体積の定義そのものです）。

### 深度から世界座標へ

W3C の Depth Sensing Module では、深度は**カメラ平面からの距離**（視線に沿った長さではない）で、
`getDepthInMeters(u,v)` の `u,v` は**ビューの正規化座標（原点は左上）**です。
WebXR の投影行列は非対称視錐台でも決まった形になるので、逆行列を使わずに

```
x = d · (ndcX + m8) / m0
y = d · (ndcY + m9) / m5
z = -d
```

で視点座標に戻せます（1 点あたり数回の掛け算だけ）。想定外の形の行列だったときは逆行列を使う経路に落ちます。

### 質を上げるためにやっていること

| 処理 | 目的 |
|------|------|
| 縁の飛び値の除去 | 隣の画素と深度が大きく飛ぶ場所（物の縁）は、奥と手前が混ざった偽の点になるので捨てる |
| 速く動かしたフレームの破棄 | 端末が 1.5m/s を超えて動いたフレームはブレるので使わない |
| 3×3 メディアン | 深度のノイズはセルごとに独立なので、中央値を取るだけでかなり落ちる |
| クロージング（膨張→収縮） | ノイズによる 1 格子の切れ目・穴を閉じ、対象が細切れになるのを防ぐ |
| RANSAC ＋ しきい値の自動調整 | 地面はふつう視界でいちばん広い平面。しきい値は計測のばらつきから自動で決める |
| ラプラス補間 | 対象の内側の未計測セルを、周りの高さから反復平均で埋める |
| 逐次平均 | 格子の高さは合計を持たずに逐次更新するので、点を何万個入れても桁落ちしない |
| 型付き配列＋開番地法ハッシュ | 毎秒 10万点を投げ込んでも GC が走らない |

## 9. 更新するとき

ファイルを直して再度 push（または再アップロード）してください。
オフライン用にキャッシュしているため、**更新後の初回起動では古い画面が出て、2回目の起動で新しい版になります**。
すぐ反映したい場合は `sw.js` の先頭にある `APP_CACHE` の版数（現在 `doryo-app-v1`）を `v2`, `v3`… と上げてください。

## 10. 書き出したデータについて

座標の原点は**スキャンを始めたときの端末の位置**、Y は鉛直上向き（単位 m）です。
**現場座標（平面直角座標）とは結び付いていません。** 位置合わせが要る場合は、
点群を CloudCompare 等に読み込んで既知点で合わせてください。

- **PLY**：CloudCompare / MeshLab / Blender で開けます（binary_little_endian）
- **格子 CSV**：点高法の計算表そのもの。「体積寄与」列を足すと表示している体積に一致します（検証済み）。
  Excel で開いて、そのまま数量計算の資料に使えます
- **JSON**：基準面の式・計算条件・結果・深度の種類・スキャンの記録が入ります。
  どの条件で出した数字かを後から示せます
